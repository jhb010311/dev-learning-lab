공부

JPA

객체를 테이블에 저장한다는 것이 무엇인지, 영속성 컨텍스트와 연관관계, 지연 로딩, 쿼리가 언제 몇 번 나가는지를 봅니다.

시작

  • JPA가 푸는 문제 — SQL을 직접 쓰면 무엇을 손으로 채워야 하나

영속성 관리

  • 영속성 컨텍스트 — JPA는 SQL을 언제 보내나
  • 엔티티의 생명주기 — 같은 setName인데 왜 어떤 때는 DB에 반영되지 않나
  • 준영속과 병합 — merge로 이름만 고쳤는데 왜 다른 값이 지워지나

엔티티 매핑

  • 엔티티 매핑과 기본 키 — 엔티티에 붙인 애노테이션은 테이블과 저장되는 값을 어떻게 바꾸나
  • 값 타입과 임베디드 타입 — 주소를 묶은 클래스는 테이블에 어떻게 저장되고, 왜 불변으로 만드나

연관관계

  • 연관관계의 주인 — 팀의 목록에 회원을 넣었는데 왜 DB의 외래 키는 비어 있나
  • 다대일, 일대다, 일대일, 다대다 — 관계의 종류에 따라 테이블과 외래 키는 어떻게 달라지나
  • 상속 관계 매핑 — 상속한 클래스는 테이블 몇 개에 어떻게 저장되나
  • 영속성 전이와 고아 객체 — 부모만 저장하거나 지우면 자식은 어떻게 되나

프록시와 로딩

  • 프록시와 지연 로딩 — 지연 로딩으로 받은 객체는 진짜 엔티티인가
  • N+1 — 주문 목록 한 번 조회했는데 쿼리는 왜 여러 번 나가나

쿼리

  • JPQL과 페치 조인 — join과 join fetch는 무엇이 다른가
  • 벌크 연산 — 한 번에 고치는 UPDATE 뒤에 엔티티는 왜 옛 값인가
  • 스프링 데이터 JPA — 구현 클래스가 없는데 리포지토리는 어떻게 동작하나
  • 동적 쿼리와 Querydsl — 검색 조건이 있을 때만 where에 붙이려면

웹 애플리케이션과 성능

  • 커넥션 풀과 OSIV — 쿼리는 금방 끝났는데 커넥션이 모자란 이유
  • 낙관적 락과 비관적 락 — 재고 3개에 주문이 동시에 몰리면
  • DTO로 바로 조회하기 — 엔티티로 조회해 옮기는 것과 DTO로 바로 조회하는 것은 무엇이 다른가
