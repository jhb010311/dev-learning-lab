이 사이트의 실습은 자바스크립트를 켜야 움직입니다. 아래는 같은 내용을 글로 적은 것입니다.

공부

DB

테이블 설계와 SQL, 인덱스와 실행 계획, 트랜잭션과 잠금, 복제와 분산까지. 데이터가 저장되고 조회되는 과정을 봅니다.

관계형 모델과 설계

  • 테이블, 키, 제약 조건 — 제약 조건이 없으면 어떤 데이터가 들어가 버리나
  • ER 모델링 — 개체 사이의 관계를 테이블로 어떻게 옮기나
  • 정규화 — 테이블을 나누지 않으면 무슨 일이 생기나

SQL

  • SELECT가 처리되는 순서 — WHERE에서는 왜 별칭과 집계 함수를 쓸 수 없나
  • JOIN과 GROUP BY — 조건을 ON에 쓰느냐 WHERE에 쓰느냐
  • 서브쿼리 — NOT IN의 결과가 왜 한 행도 없나
  • 윈도우 함수 — 행을 줄이지 않고 순위와 누계를 붙이려면
  • OFFSET과 키셋 페이징 — 뒤쪽 페이지일수록 느려지는 이유
  • 뷰, 프로시저, 트리거 — INSERT 한 줄을 실행했는데 왜 재고가 줄었나

인덱스와 실행 계획

  • 이진 탐색과 B-트리 — 정렬돼 있으면 절반씩 버릴 수 있다
  • 인덱스와 풀 스캔 — 인덱스가 있는데 왜 안 탈까
  • 복합·커버링 인덱스 — 복합 인덱스는 컬럼 순서대로만 쓸 수 있다
  • 실행 계획 읽기 — EXPLAIN 한 줄에서 무엇을 읽어야 하나
  • 조인 알고리즘 — 조인 컬럼에 인덱스가 없으면 DB는 어떻게 짝을 찾나

트랜잭션과 잠금

  • 트랜잭션 기본 — 출금은 됐는데 입금이 안 됐다면
  • 격리 수준 — 다른 트랜잭션이 바꾸는 중인 데이터가 내게 어떻게 보이나
  • 갭 락과 넥스트 키 락 — 없는 행을 조회했는데 왜 INSERT가 막히나
  • 재고 차감과 락 — 재고 3개에 주문이 동시에 몰리면
  • DB의 교착 상태 — 두 트랜잭션이 서로를 기다리면 DB는 어떻게 끝내나

저장과 복구

  • Undo와 Redo 로그 — 커밋 직후 전원이 꺼져도 데이터가 남는 이유
  • 버퍼 풀과 페이지 — 행 하나를 읽는데 왜 16KB를 통째로 읽나

확장과 분산

  • 복제 지연과 CAP — 방금 저장했는데 조회하니 옛날 값이 나온다
  • 샤딩 — 데이터를 여러 DB에 나누면 생기는 일
  • 파티셔닝 — 테이블을 조각내면 조회는 어느 조각을 읽나
  • 키-값 저장소 Redis — 명령 하나가 느리면 모두가 기다린다
  • NoSQL과 문서 모델 — 주문을 테이블 셋에 나눌까, 문서 하나에 담을까
