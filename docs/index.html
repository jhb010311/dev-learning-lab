개발 학습 실습실

설정을 바꾸고 실행을 눌러, 개념이 어떻게 움직이는지 직접 봅니다.

자바, 스프링, JPA, 데이터베이스, 네트워크, 보안의 개념을 설정을 바꿔 실행해 보며 익히는 무료 실습실

Java

문법부터 객체 지향, 컬렉션, 스레드, JVM까지. 코드가 실행될 때 안에서 무슨 일이 일어나는지를 봅니다.

기본 문법

  • 변수와 타입 — 변수를 다른 변수에 대입하면 무엇이 복사되나
  • 연산자와 형변환 — 7 / 2는 왜 3.5가 아니라 3이 나오나
  • 조건문과 반복문 — 반복문은 몇 번 돌고, 어디에서 멈추나
  • 배열 — 배열 변수를 대입하면 배열이 복사되나

클래스와 객체

  • 클래스, 객체, 생성자 — new를 하면 어떤 순서로 무슨 일이 일어나나
  • static과 인스턴스 — b만 건드렸는데 왜 a의 값도 바뀌나
  • 상속과 오버라이딩 — 자식 객체를 만들 때 부모 생성자는 언제 실행되나
  • 다형성과 메서드 선택 — 어느 메서드가 실행될지는 누가, 언제 정하나
  • 인터페이스와 추상 클래스 — 둘 다 new로 못 만드는데 무엇이 다른가
  • 접근 제어자와 캡슐화 — private, protected, public은 어디까지 열어 주나
  • 내부 클래스와 익명 클래스 — 클래스 안에 만든 클래스는 바깥 객체와 어떻게 이어져 있나
  • 불변과 방어적 복사 — final을 붙였는데 값이 바뀌었다
  • 전략 패턴 — 결제 수단이 하나 늘 때 고쳐야 하는 곳

자주 쓰는 클래스

  • ==와 equals — 같은 값인데 ==는 왜 false가 나오나
  • equals와 hashCode — equals만 고치면 왜 HashMap에서 못 찾나
  • String, StringBuilder — 문자열 메서드를 불렀는데 왜 원본이 그대로인가
  • 날짜와 시간 — 1월 31일에 한 달을 더하면 며칠이 되나
  • Optional — 값이 있는데도 orElse의 기본값 코드는 왜 실행되나

예외

  • 예외와 finally — 예외가 나면 어느 블록이 어떤 순서로 실행되나
  • 체크 예외와 언체크 예외 — 어떤 예외는 왜 처리하지 않으면 컴파일조차 안 되나

제네릭, 열거형, 애너테이션

  • 제네릭 — List<Integer>의 <Integer>는 무엇을 막아 주나
  • 열거형(enum) — enum을 숫자로 저장해 두면 왜 다른 상수가 되어 돌아오나
  • 애너테이션 — @를 붙이기만 하면 정말 무슨 일이 일어나나

컬렉션

  • ArrayList와 LinkedList — 같은 연산인데 드는 일의 양이 다르다
  • HashMap 내부 — HashMap은 키를 어디에 넣고 어떻게 찾나
  • Set과 Map의 종류 — 같은 값을 넣었는데 꺼내는 순서가 왜 다른가
  • 스택·큐·우선순위 큐 — 넣은 순서와 꺼내는 순서
  • 순회 중 삭제 — 반복문 안에서 원소를 지우면
  • 정렬과 Comparator — 정렬 순서는 누가 정하고, 빼서 비교하면 왜 틀리나

람다와 스트림

  • 람다와 함수형 인터페이스 — 람다에 적은 코드는 언제 실행되나
  • 스트림 지연 평가 — 스트림은 적힌 순서대로 실행되지 않는다
  • 스트림으로 모으기 — 스트림의 결과를 어떤 모양으로 모으나
  • 병렬 스트림과 공용 풀 — 남의 병렬 스트림 때문에 내 코드가 느려진다

스레드와 동시성

  • 프로세스와 스레드 — 일꾼을 늘리는 두 가지 방법
  • 스레드의 생성과 상태 — run()을 직접 부르면 왜 새 스레드가 생기지 않나
  • 경쟁 상태 — count++는 왜 숫자를 잃어버리나
  • 교착 상태 — 서로 기다리다 둘 다 멈춘다
  • 스레드 풀 — 스레드를 늘리면 무엇이 달라지나
  • 스레드 수와 컨텍스트 스위칭 — 스레드를 늘린다고 계속 빨라지지는 않는다
  • 순차 호출과 병렬 호출 — 외부 호출 여러 개를 차례로 할까 한꺼번에 할까
  • 블로킹·논블로킹·가상 스레드 — 기다리는 동안 스레드는 무엇을 하나

JVM

  • 스택과 힙 — 메서드를 부를 때마다 메모리에서는 무슨 일이
  • GC와 메모리 누수 — 버려진 객체는 누가 언제 치우나
  • JIT 워밍업 — 배포 직후의 첫 요청들은 왜 느린가
  • 클래스 로딩과 초기화 — 클래스의 static 블록은 언제 실행되나

입출력

  • 입출력 스트림과 버퍼 — write를 했는데 왜 파일이 비어 있나
  • 직렬화 — 저장한 객체를 되살리면 무엇이 돌아오나

Spring

컨테이너와 의존성 주입, AOP와 트랜잭션, 웹 요청이 처리되는 길, 스프링 부트가 대신 해 주는 일을 봅니다.

IoC 컨테이너와 DI

  • 스프링 컨테이너와 빈 — new를 쓰지 않았는데 객체는 누가 만들어 넣어 주나
  • 빈 생성과 주입 — 스프링은 객체를 어떤 순서로 만들고 연결하나
  • 싱글톤 빈과 상태 — 내 주문에 다른 사람 이름이 찍혔다
  • 빈 스코프 — 프로토타입 빈인데 왜 객체가 하나뿐인가
  • 빈 생명주기 콜백 — 생성자에서 주입받은 필드를 썼더니 왜 null인가

AOP와 프록시

  • 프록시와 자기 호출 — 애노테이션을 붙였는데 왜 동작하지 않나
  • AOP: 어드바이스와 포인트컷 — 어드바이스는 어느 메서드에, 어떤 순서로 끼어드나

데이터 접근과 트랜잭션

  • 트랜잭션 기본 — 출금은 됐는데 입금이 안 됐다면
  • 트랜잭션 전파 — 예외가 나면 어디까지 롤백되나
  • JdbcTemplate과 예외 변환 — JdbcTemplate은 무엇을 대신 해 주고, 예외를 무엇으로 바꾸나
  • 커넥션 풀과 OSIV — 쿼리는 금방 끝났는데 커넥션이 모자란 이유

웹 MVC

  • 서블릿 — HTTP 요청이 자바 코드에 닿기까지
  • MVC 요청 흐름 — 요청 하나가 컨트롤러에 닿기까지, 그리고 돌아가기까지
  • 요청 매핑과 파라미터 바인딩 — 요청에 실어 보낸 값은 어떻게 메서드의 파라미터가 되나
  • 검증 — 필드에 @NotBlank를 붙였는데 왜 빈 값이 그대로 들어오나
  • REST API와 메시지 컨버터 — 컨트롤러가 돌려준 객체는 어디서 JSON이 되나

스프링 부트

  • 스프링 부트 자동 설정 — 의존성만 추가했는데 왜 빈이 생기나
  • 설정 우선순위 — 같은 설정이 여러 곳에 있으면 어느 값이 이기나
  • 액추에이터와 헬스 체크 — 결제사 연결이 끊겼을 때 헬스 체크는 무엇이라고 답하나

그 밖의 기능

  • 테스트 — 테스트를 실행할 때 스프링 컨텍스트에는 무엇이 들어가고, 몇 번 만들어지나
  • 외부 API 호출과 타임아웃 — 다른 서버를 호출했는데 답이 오지 않으면 언제까지 기다리나
  • 캐시 추상화 — @Cacheable을 붙이면 메서드 본문은 언제 실행되지 않나
  • 시큐리티 필터 체인 — 401과 403은 어디에서 갈리나

JPA

객체를 테이블에 저장한다는 것이 무엇인지, 영속성 컨텍스트와 연관관계, 지연 로딩, 쿼리가 언제 몇 번 나가는지를 봅니다.

시작

  • JPA가 푸는 문제 — SQL을 직접 쓰면 무엇을 손으로 채워야 하나

영속성 관리

  • 영속성 컨텍스트 — JPA는 SQL을 언제 보내나
  • 엔티티의 생명주기 — 같은 setName인데 왜 어떤 때는 DB에 반영되지 않나
  • 준영속과 병합 — merge로 이름만 고쳤는데 왜 다른 값이 지워지나

엔티티 매핑

  • 엔티티 매핑과 기본 키 — 엔티티에 붙인 애노테이션은 테이블과 저장되는 값을 어떻게 바꾸나
  • 값 타입과 임베디드 타입 — 주소를 묶은 클래스는 테이블에 어떻게 저장되고, 왜 불변으로 만드나

연관관계

  • 연관관계의 주인 — 팀의 목록에 회원을 넣었는데 왜 DB의 외래 키는 비어 있나
  • 다대일, 일대다, 일대일, 다대다 — 관계의 종류에 따라 테이블과 외래 키는 어떻게 달라지나
  • 상속 관계 매핑 — 상속한 클래스는 테이블 몇 개에 어떻게 저장되나
  • 영속성 전이와 고아 객체 — 부모만 저장하거나 지우면 자식은 어떻게 되나

프록시와 로딩

  • 프록시와 지연 로딩 — 지연 로딩으로 받은 객체는 진짜 엔티티인가
  • N+1 — 주문 목록 한 번 조회했는데 쿼리는 왜 여러 번 나가나

쿼리

  • JPQL과 페치 조인 — join과 join fetch는 무엇이 다른가
  • 벌크 연산 — 한 번에 고치는 UPDATE 뒤에 엔티티는 왜 옛 값인가
  • 스프링 데이터 JPA — 구현 클래스가 없는데 리포지토리는 어떻게 동작하나
  • 동적 쿼리와 Querydsl — 검색 조건이 있을 때만 where에 붙이려면

웹 애플리케이션과 성능

  • 커넥션 풀과 OSIV — 쿼리는 금방 끝났는데 커넥션이 모자란 이유
  • 낙관적 락과 비관적 락 — 재고 3개에 주문이 동시에 몰리면
  • DTO로 바로 조회하기 — 엔티티로 조회해 옮기는 것과 DTO로 바로 조회하는 것은 무엇이 다른가

DB

테이블 설계와 SQL, 인덱스와 실행 계획, 트랜잭션과 잠금, 복제와 분산까지. 데이터가 저장되고 조회되는 과정을 봅니다.

관계형 모델과 설계

  • 테이블, 키, 제약 조건 — 제약 조건이 없으면 어떤 데이터가 들어가 버리나
  • ER 모델링 — 개체 사이의 관계를 테이블로 어떻게 옮기나
  • 정규화 — 테이블을 나누지 않으면 무슨 일이 생기나

SQL

  • SELECT가 처리되는 순서 — WHERE에서는 왜 별칭과 집계 함수를 쓸 수 없나
  • JOIN과 GROUP BY — 조건을 ON에 쓰느냐 WHERE에 쓰느냐
  • 서브쿼리 — NOT IN의 결과가 왜 한 행도 없나
  • 윈도우 함수 — 행을 줄이지 않고 순위와 누계를 붙이려면
  • OFFSET과 키셋 페이징 — 뒤쪽 페이지일수록 느려지는 이유
  • 뷰, 프로시저, 트리거 — INSERT 한 줄을 실행했는데 왜 재고가 줄었나

인덱스와 실행 계획

  • 이진 탐색과 B-트리 — 정렬돼 있으면 절반씩 버릴 수 있다
  • 인덱스와 풀 스캔 — 인덱스가 있는데 왜 안 탈까
  • 복합·커버링 인덱스 — 복합 인덱스는 컬럼 순서대로만 쓸 수 있다
  • 실행 계획 읽기 — EXPLAIN 한 줄에서 무엇을 읽어야 하나
  • 조인 알고리즘 — 조인 컬럼에 인덱스가 없으면 DB는 어떻게 짝을 찾나

트랜잭션과 잠금

  • 트랜잭션 기본 — 출금은 됐는데 입금이 안 됐다면
  • 격리 수준 — 다른 트랜잭션이 바꾸는 중인 데이터가 내게 어떻게 보이나
  • 갭 락과 넥스트 키 락 — 없는 행을 조회했는데 왜 INSERT가 막히나
  • 재고 차감과 락 — 재고 3개에 주문이 동시에 몰리면
  • DB의 교착 상태 — 두 트랜잭션이 서로를 기다리면 DB는 어떻게 끝내나

저장과 복구

  • Undo와 Redo 로그 — 커밋 직후 전원이 꺼져도 데이터가 남는 이유
  • 버퍼 풀과 페이지 — 행 하나를 읽는데 왜 16KB를 통째로 읽나

확장과 분산

  • 복제 지연과 CAP — 방금 저장했는데 조회하니 옛날 값이 나온다
  • 샤딩 — 데이터를 여러 DB에 나누면 생기는 일
  • 파티셔닝 — 테이블을 조각내면 조회는 어느 조각을 읽나
  • 키-값 저장소 Redis — 명령 하나가 느리면 모두가 기다린다
  • NoSQL과 문서 모델 — 주문을 테이블 셋에 나눌까, 문서 하나에 담을까

네트워크

주소를 입력한 뒤 응답이 오기까지. DNS, TCP, HTTP, TLS와 그 사이에 놓인 장비들을 봅니다.

큰 그림

  • 주소 입력부터 응답까지 — 주소창에 입력하고 엔터를 누르면
  • 계층 구조와 캡슐화 — 1500바이트를 보냈는데 왜 전선에는 1616바이트가 지나갈까

주소와 이름

  • URL의 구조 — 검색어 "A&B"를 주소에 붙였더니 서버에는 "A"만 도착했다
  • DNS — 도메인 이름의 주소는 누가 알고 있고, 바꾸면 언제 반영될까
  • IP 주소와 서브넷 — 앞의 세 숫자가 같은 두 IP 주소는 같은 네트워크일까
  • 스위치와 라우터 — 받는 IP는 서버인데 왜 라우터의 MAC 주소로 보내나

전송 계층

  • 소켓과 포트 — 한 컴퓨터의 여러 프로그램 가운데 누가 이 데이터를 받나
  • TCP 연결과 재전송 — 패킷이 사라지면 누가 알아채고 다시 보내나
  • TCP와 UDP — 세 번에 나눠 보낸 데이터는 세 번에 나뉘어 도착하나
  • 흐름 제어와 혼잡 제어 — TCP는 한 번에 얼마나 보낼지를 어떻게 정하나

HTTP

  • HTTP 메시지와 상태 코드 — 요청과 응답은 이렇게 생긴 글자다
  • HTTP/1.1, 2, 3 — 파일 30개를 받을 때 버전마다 무엇이 다른가
  • 쿠키 — 기억하지 못하는 서버에게 매번 이름표를 내민다
  • HTTP 캐시와 ETag — 같은 파일을 또 받을 필요가 있을까
  • 재시도와 멱등성 — 응답을 못 받아서 다시 보냈더니
  • 리다이렉션 — "다른 주소로 가라"는 응답을 받으면 다음 요청은 어떻게 나가나
  • 내용 협상과 압축 — 같은 주소인데 왜 사람마다 다른 응답을 받나
  • CORS — Postman에서는 되는데 브라우저에서만 막히는 이유
  • 폴링·SSE·WebSocket — 서버에서 생긴 일을 브라우저에 알리는 네 가지 방법

보안 연결

  • TLS 핸드셰이크 — https의 자물쇠가 잠기기까지

웹 서버 앞의 장비

  • 로드밸런서와 스케일 아웃 — 서버를 늘리면 어디까지 버티나
  • 프록시와 리버스 프록시 — 프록시 뒤의 서버는 누가 요청했는지 어떻게 아나
  • CDN — 원본을 바꿨는데 왜 사용자는 아직 옛 파일을 받나

보안

누구인지 확인하는 인증, 무엇을 할 수 있는지 정하는 인가, 웹 공격과 방어, 암호 기술을 봅니다.

인증

  • 세션과 JWT — 로그인 상태는 어디에 저장되나
  • 쿠키 — 기억하지 못하는 서버에게 매번 이름표를 내민다
  • 비밀번호 해시 — DB가 털렸을 때 비밀번호는 얼마나 버티나
  • JWT의 구조와 검증 — 누구나 읽을 수 있는 토큰을 서버는 어떻게 믿나
  • OAuth 로그인 흐름 — "카카오로 로그인"을 누르면 오가는 것들
  • 세션 하이재킹과 세션 고정 — 세션 ID를 아는 사람이 곧 그 사용자다

인가

  • 시큐리티 필터 체인 — 401과 403은 어디에서 갈리나
  • 접근 제어 — 로그인한 사용자가 주소의 번호만 바꾸면 남의 주문이 보이나
  • 메서드 보안 — 메서드에 붙인 권한 검사는 언제 실행되고 언제 빠지나

웹 공격과 방어

  • 웹 공격 세 가지 — 입력값을 그대로 믿으면 생기는 일
  • CORS — Postman에서는 되는데 브라우저에서만 막히는 이유
  • 클릭재킹과 오픈 리다이렉트 — 내 화면이 남의 페이지에 숨겨지거나, 내 주소가 남의 사이트로 넘겨주는 일을 어떻게 막나
  • 정보 누출 — 오류 응답과 로그인 실패 글귀는 무엇을 밖으로 알려 주나
  • 요청 수 제한 — 초당 5건까지만 받는다는 것의 세 가지 의미
  • 의존성과 공급망 — 내가 적지 않은 라이브러리는 어떻게 내 프로그램에 들어오고, 그 버전은 누가 정하나

암호 기술

  • 해시·암호화·서명 — 숨기는 것, 확인하는 것, 되돌릴 수 없는 것
  • TLS 핸드셰이크 — https의 자물쇠가 잠기기까지

아키텍처와 운영

트래픽이 늘 때, 서비스를 나눌 때, 배포하고 지켜볼 때의 주제입니다.

대용량 트래픽

  • 로드밸런서와 스케일 아웃 — 서버를 늘리면 어디까지 버티나
  • 캐시와 TTL — 캐시를 두면 DB 조회가 얼마나 줄고, 언제 다시 몰리나
  • Redis의 한 줄 처리 — 명령 하나가 느리면 모두가 기다린다
  • 요청 수 제한 — 초당 5건까지만 받는다는 것의 세 가지 의미

메시지와 비동기

  • 메시지 큐 기본 — 직접 부르지 않고 쪽지를 남긴다
  • Kafka 파티션과 컨슈머 — 컨슈머를 늘렸는데 왜 처리량이 그대로인가

서비스 분리

  • 서킷 브레이커 — 죽은 서비스를 계속 부르면 나까지 죽는다
  • Saga와 Outbox — 서비스마다 DB가 따로일 때 "전부 성공 아니면 전부 취소"를 어떻게 하나
  • 게이트웨이와 점진적 전환 — 거대한 서버를 멈추지 않고 조금씩 떼어 내기

배포와 운영

  • CI/CD 파이프라인 — 코드를 올리면 기계가 대신 확인하고 배포한다
  • 배포 전략 — 서비스를 끊지 않고 새 버전으로 바꾸려면
  • 컨테이너와 가상 머신 — 컨테이너는 왜 가볍고 빨리 뜨나
  • 쿠버네티스 자가 치유 — 컨테이너가 죽으면 누가 다시 띄우나

관측

  • 평균과 백분위 — 평균 응답 시간은 멀쩡한데 왜 느리다는 불만이 오나
  • 분산 추적 — 요청 하나가 느린데 어느 서비스 탓인가

협업

  • merge와 rebase — 두 브랜치를 합치는 세 가지 모양
