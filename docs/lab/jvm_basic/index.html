컴파일과 JVM

자바 코드는 어떻게 실행되는가

우리가 쓰는 Hello.java 파일은 사람이 읽는 글입니다. java Hello로 실행하는 방식에서는 이 글이 그대로 실행되는 것이 아니라 두 단계를 거칩니다. 터미널(명령을 글자로 입력하는 창)에서 javac Hello.java 명령을 쓰면 javac라는 프로그램(컴파일러)이 이 글을 읽어 Hello.class 파일로 바꿉니다. 이 일을 컴파일이라고 합니다. Hello.class에는 JVM이 읽는 바이트코드가 들어 있습니다. 이어서 java Hello 명령을 쓰면 JVM(자바 가상 머신)이 뜨고, JVM이 Hello.class를 읽어 main을 실행합니다. 이 실습은 javac 줄을 지우고, 소스의 글을 틀리게 하거나 컴파일한 뒤에 고쳐 가며 실제 javac와 java 명령을 실행해, Hello.class가 만들어지는지와 java Hello가 무엇을 실행하는지를 봅니다.

실행으로 대조 · JDK 21의 javac와 java 명령으로 여섯 가지 조합을 실제로 실행해 대조

이 실습에 나오는 개념

컴파일과 javac
컴파일은 사람이 쓴 소스 코드를 JVM이 실행할 수 있는 형태로 바꾸는 일이고, 자바에서 이 일을 하는 프로그램이 javac(자바 컴파일러)이다. javac 명령은 확장자가 .java인 소스 파일을 읽어 확장자가 .class인 class 파일로 바꾸며, 따로 정하지 않으면 class 파일을 소스 파일과 같은 폴더에 만든다. javac는 코드를 바꾸기만 하고 실행하지는 않으므로, 컴파일한 뒤에 JVM에서 실행하는 단계가 따로 있다. 소스에 오류가 있으면 javac가 오류 메시지를 출력하고, 오류가 없으면 class 파일이 출력 폴더에 놓인다. 소스 파일을 고쳐도 이미 만든 class 파일은 바뀌지 않으므로, 고친 내용을 쓰려면 javac로 다시 컴파일해야 한다.
.class 파일
.class 파일은 컴파일의 결과로 만들어지는 파일로, JVM이 읽는 class 파일 형식으로 되어 있다. 이 안에는 JVM의 명령어(바이트코드)와 기호 표, 그 밖의 부가 정보가 들어 있고, 파일의 맨 앞 4바이트는 이 형식임을 알리는 0xCAFEBABE이다. JVM은 자바 언어를 알지 못하고 이 class 파일 형식만 안다. java Hello처럼 클래스 이름으로 실행하면 JVM은 클래스 경로에서 그 이름의 클래스를 찾는데, 클래스 경로를 따로 정하지 않으면 현재 폴더이다. 그래서 같은 폴더에 Hello.java가 있어도 Hello.class가 없으면 Hello 클래스를 찾을 수 없다는 오류가 난다.
JVM(자바 가상 머신)
자바 바이트코드를 읽어 실행하는 프로그램이다. 운영체제마다 그에 맞는 JVM이 있어서, 한 번 컴파일한 자바 프로그램을 수정 없이 여러 운영체제에서 실행할 수 있다. 클래스를 읽어 들이고, 메모리를 관리하고(가비지 컬렉션), 바이트코드를 기계어로 바꿔 실행하는 일을 맡는다.
바이트코드
자바 컴파일러(javac)가 소스 코드를 변환해 만든 중간 형태의 코드로 .class 파일에 담긴다. 특정 CPU나 운영체제의 기계어가 아니라 JVM이 이해하는 명령어라서 어느 플랫폼의 JVM에서든 실행된다.

이렇게 바꿔 보세요

  • 처음 설정으로 — javac가 Hello.class를 만들고, JVM이 Hello.class를 읽어 안녕을 출력합니다.
  • javac 줄을 지우면 — Hello.class가 만들어지지 않아 java Hello가 실행할 것을 찾지 못합니다.
  • 세미콜론을 빼면 — javac가 문법 오류를 알리고 Hello.class를 만들지 않습니다.
  • 컴파일한 뒤 소스만 고치면 — 고치기 전에 만든 Hello.class가 실행되어 안녕이 출력됩니다.
  • javac 줄도 지우고 세미콜론도 빼면 — javac가 읽은 적이 없어 문법 오류는 알려지지 않고, 같은 이유로 실행에 실패합니다.

처음 설정으로 실행하면

  1. Hello.java 파일에는 사람이 읽는 자바 코드가 적혀 있고, 이 코드는 "안녕"을 출력하라는 뜻입니다. 이 코드를 실행하려면 두 단계를 거칩니다. 먼저 javac 명령이 Hello.java 파일을 Hello.class라는 다른 파일로 바꾸고(컴파일), 그다음 java 명령이 Hello.class 파일을 읽어 실행합니다. java 명령이 찾는 것은 Hello.java 글이 아니라 Hello.class 파일입니다.
  2. 터미널에서 javac Hello.java 명령을 실행합니다. javac 컴파일러가 Hello.java 파일을 처음부터 읽으며 자바 문법에 맞는지 확인하고, 맞으면 읽은 내용을 바이트코드로 바꿔 Hello.class 파일에 씁니다. 이 단계에서는 코드를 바꾸기만 하고 실행하지 않으므로 아무것도 출력되지 않습니다.
  3. javac 명령이 오류 없이 끝났습니다(종료 코드 0). 폴더에 Hello.class 파일이 생겼습니다. 이 파일에는 사람이 읽는 글이 아니라 JVM이 읽는 바이트코드가 들어 있습니다. Hello.java 파일은 그대로 남아 있습니다.
  4. 터미널에서 java Hello 명령을 실행합니다. java 명령이 JVM을 띄우고, JVM이 현재 폴더에서 Hello.class 파일을 찾아 읽어 들입니다. JVM이 읽는 것은 Hello.class 파일이고 Hello.java 파일은 읽지 않습니다.
  5. JVM이 Hello.class 안의 main을 실행하고, main의 println이 안녕을 출력합니다.

실행 결과

  • Hello.java는 사람이 읽는 자바 코드이고, javac 명령이 이것을 JVM이 읽는 바이트코드 파일 Hello.class로 바꿉니다(컴파일). java 명령이 띄운 JVM이 Hello.class를 읽어 main을 실행하면 안녕이 출력됩니다. 실행된 것은 Hello.java가 아니라 Hello.class입니다.
  • 컴파일은 코드를 바꿀 뿐 실행하지 않습니다. javac Hello.java 명령을 쓸 때는 아무것도 출력되지 않았고, java Hello 명령을 쓸 때 안녕이 출력되었습니다.

코드

# Hello.java
public class Hello {
    // main: java 명령이 가장 먼저 부르는 메서드
    public static void main(String[] args) {
        System.out.println("안녕");
    }
}

# 터미널
# 컴파일: javac가 Hello.java를 읽고 Hello.class를 만든다
javac Hello.java
# 실행: java가 JVM을 띄워 Hello.class의 main을 실행한다
java Hello

이 모형의 전제

컴파일러와 실행 환경은 JDK 21.0.12.1(javac 21, java 21)입니다. 여섯 가지 조합을 모두, 화면의 코드와 같은 글(# Hello.java 구역과 # 터미널 구역)을 조합마다 빈 폴더에 만들고, 그 글에서 소스 파일과 명령을 읽어 실제 javac 프로그램과 java 프로그램을 프로세스로 띄워 실행한 결과와 대조했습니다. 대조한 것은 폴더에 Hello.class가 생겼는지, javac의 종료 코드와 표준 출력, 첫 오류 메시지와 오류 개수와 오류가 난 줄, java의 종료 코드와 출력과 오류 메시지, 고치는 일이 Hello.class를 바꾸지 않는지, Hello.class 파일 맨 앞 네 바이트(CAFEBABE)와 버전(65, 자바 21)입니다. 고친 뒤 javac 명령을 다시 쓰면 "잘 가"가 출력되는 것도 따로 실행해 확인했습니다. 실행한 명령은 화면과 두 가지가 다릅니다. 출력 글자와 오류 메시지를 같은 방식으로 읽으려고 javac와 java에 출력 인코딩을 UTF-8로, 메시지 언어를 영어로 하는 옵션(-Dstdout.encoding=UTF-8, -Duser.language=en 등)을 더했습니다. 옵션 없이 이 PC(한국어 Windows)에서 java Hello 명령을 쓰면 같은 오류가 한국어 메시지로 나옵니다. 문서는 직접 열어 확인했습니다. Java 가상 머신 명세 Java SE 21 판 1.2절(JVM은 자바 언어를 모르고 class 파일 형식만 안다, class 파일에는 JVM 명령어인 바이트코드가 들어 있다), 같은 명세 4.1절(class 파일 맨 앞의 magic 값은 0xCAFEBABE, 자바 SE 21의 major 버전은 65, 이 장은 일부만 읽었습니다), JDK 21 javac 도구 문서(.java 소스 파일을 읽어 .class 파일로 컴파일한다, 따로 정하지 않으면 소스와 같은 폴더에 만든다, 오류가 없으면 class 파일을 출력 폴더에 놓는다), java 도구 문서(JVM을 띄워 지정한 클래스를 읽고 main을 부른다, 클래스 경로를 정하지 않으면 현재 폴더이다, 앞쪽 일부만 읽었고 종료 코드 절은 읽지 못했습니다)를 따랐습니다. 오류가 났을 때 Hello.class를 만들지 않는 것, 종료 코드가 0과 1이라는 것, 오류 메시지의 글은 문서가 정한 것이 아니라 이 JDK에서 관찰한 것입니다. 화면의 코드는 폴더에 Hello.java 하나만 있는 상황으로 줄였고, 패키지가 있는 클래스, 클래스 경로 설정, jar 파일, IDE나 빌드 도구가 대신 컴파일하는 것은 다루지 않았습니다. java Hello.java처럼 소스 파일을 바로 실행하는 방법(소스 파일 모드)도 화면에서 쓰지 않았습니다. 이 JDK에서 실행해 보니 Hello.class를 만들지 않고 안녕을 출력했고(java 문서도 소스를 메모리에 컴파일해 실행한다고 설명합니다), 세미콜론이 빠진 소스는 이 방식에서도 같은 컴파일 오류로 실패했습니다. 또 컴파일에 성공한 뒤 소스를 틀리게 고치고 javac 명령을 다시 쓰면 오류가 나지만 옛 Hello.class는 폴더에 그대로 남아 java Hello 명령이 옛 코드를 실행하는 것도 확인했으나, 화면에서는 다루지 않았습니다. JVM이 Hello.class를 읽어 들이는 방식은 "세부 동작 실습: 클래스 로딩과 초기화"에서, 바이트코드를 기계어로 다시 컴파일하는 JIT는 "세부 동작 실습: JIT 워밍업"에서 다룹니다.
