변수와 타입

변수는 무엇이고, 타입은 무엇을 정하는가

왜 생겼나 — 계산에 쓰는 값을 매번 숫자로 직접 적으면, 같은 값을 여러 곳에 쓸 때 고칠 곳도 여러 곳이 되고, 나이가 한 살 늘어나는 것처럼 실행하는 동안 바뀌는 값을 이어서 쓸 수 없다. 변수는 값에 이름을 붙여 저장해 두고 그 이름으로 다시 읽고 바꾸게 하며, 자바는 변수마다 타입을 정하게 해서 엉뚱한 종류의 값을 쓰는 실수를 실행하기 전에 컴파일러가 잡게 한다.

지금 어디에 쓰나 — 자바 코드 어디서나 본다. 사용자가 입력한 이름, 장바구니에 고른 상품의 개수와 합계, 반복하면서 지금 몇 번째인지 세는 i 같은 값이 모두 변수로 다뤄진다. 한 번 정한 뒤 바뀌면 안 되는 값은 final을 붙여 선언해서 다시 대입하지 못하게 한다.

변수는 값을 저장해 두는 공간에 붙인 이름입니다. int 같은 기본형 변수에는 값 자체가, String 같은 참조형 변수에는 객체가 아니라 객체를 가리키는 참조가 저장됩니다. int age = 20;이라는 한 줄은 세 부분으로 되어 있습니다. int는 타입으로, 이 변수에는 정수만 담는다는 뜻입니다. age는 이름이고, 20은 처음에 담을 값입니다. 이 줄을 선언이라고 하며, 선언을 읽은 컴파일러는 "age는 int 변수다"라고 기억해 두고 그 뒤의 줄들이 이 기억에 맞는지 실행하기 전에 확인합니다. 이 실습은 타입 int를 지우고, 담는 값을 바꾸고, 값을 아예 담지 않기도 하며 같은 코드를 컴파일하고 실행해, 컴파일러가 무엇을 알려 주고 무엇이 출력되는지를 봅니다.

실행으로 대조 · JDK 21에서 여섯 가지 조합을 javax.tools로 컴파일하고 실행해 대조

이 실습에 나오는 개념

변수
변수는 값을 저장해 두는 공간에 붙인 이름이다. int 같은 기본형 변수에는 값 자체가, String 같은 참조형 변수에는 객체가 아니라 객체를 가리키는 참조가 저장된다. 모든 변수에는 컴파일할 때 이미 정해진 타입이 있고, 그 타입이 어떤 종류의 값을 저장할 수 있는지를 정한다. 예를 들어 int age;로 선언한 변수는 정수만 저장할 수 있고, int는 -2147483648부터 2147483647까지의 32비트 정수이다. 변수에 값을 저장하는 것은 = 로 하며, age = age + 1;은 "오른쪽을 계산한 값을 왼쪽 변수에 저장한다"는 뜻이다. 저장된 값은 바뀔 수 있지만 변수의 이름과 타입은 바뀌지 않는다. 타입에 맞지 않는 값을 저장하려 하면 컴파일 오류이다.
선언과 초기화
왜 생겼나 — 이름을 미리 밝히지 않고 바로 쓸 수 있으면, 이름을 잘못 친 줄이 새 변수를 하나 더 만든 것으로 처리되어 실수가 드러나지 않는다. 자바는 쓰기 전에 이름과 타입을 먼저 선언하게 해서, 이런 오타를 실행하기 전에 컴파일러가 찾게 한다.
지금 어디에 쓰나 — 메서드 안에서 합계나 횟수처럼 계산하며 바뀌는 값을 둘 때 int count = 0;처럼 선언하면서 처음 값을 바로 주는 꼴을 흔히 쓴다. if 문의 갈래마다 값이 다르면 선언만 먼저 하고 갈래마다 값을 정한다.
메서드 안에서 변수를 만드는 줄을 지역 변수 선언이라고 하며 타입, 이름, 그리고 선택적으로 = 뒤에 처음 저장할 값(초기화)을 적는다. int age;는 선언만 한 것이고 int age = 20;은 선언하면서 초기화한 것이다. 선언하지 않은 이름을 쓰면 컴파일러가 그 이름을 찾지 못해 오류를 낸다. 지역 변수는 필드와 달리 0 같은 기본값이 저절로 들어가지 않으므로, 값을 읽기 전에 반드시 값이 저장돼 있어야 하고 아니면 컴파일 오류이다. 값을 저장하는 줄 = 의 왼쪽에 쓴 이름은 읽는 것으로 치지 않는다.
타입
왜 생겼나 — 값의 종류를 정하지 않으면 글자에 곱셈을 하거나 없는 메서드를 부르는 실수가 프로그램을 실행해 그 줄에 닿아야 드러난다. 자바의 타입은 이런 실수를 실행 전, 컴파일할 때 찾아 준다.
지금 어디에 쓰나 — 변수, 매개변수, 메서드가 돌려주는 값을 선언할 때 적는다. 인텔리제이 같은 편집기는 타입을 보고 그 값에 부를 수 있는 메서드 목록을 보여 준다.
타입은 변수가 가리키거나 가질 수 있는 값의 종류를 정하는 이름이다. 자바의 타입은 기본형과 참조형으로 나뉘고, 참조형에는 클래스 타입, 인터페이스 타입, 타입 변수, 배열 타입이 있다. class나 interface 선언이 있어야 그 이름을 타입으로 쓸 수 있다. 자바가 주는 List(인터페이스)와 ArrayList(클래스)도 그렇게 선언된 타입이다. 컴파일러는 변수에 값을 넣는 줄마다, 그 값의 타입이 변수의 타입과 같거나 그 하위 타입인지 확인하고, 변수로 부를 수 있는 메서드도 변수의 타입에서 찾는다. 그래서 List 타입 변수로는 실제 객체가 ArrayList여도 ArrayList에만 있는 trimToSize를 부를 수 없다.
기본형과 참조형
자바의 타입은 기본형과 참조형 두 가지로 나뉜다. 기본형은 byte, short, int, long, float, double, char, boolean의 여덟 가지이며, 변수가 값 자체를 담는다. 참조형은 클래스, 인터페이스, 배열처럼 그 밖의 모든 타입이며, 변수가 객체 자체가 아니라 객체를 가리키는 참조를 담는다. 그래서 기본형 변수를 대입하면 값이 복사되어 두 변수가 서로 영향을 주지 않지만, 참조형 변수를 대입하면 참조가 복사되어 두 변수가 같은 객체를 가리키게 된다. 참조형 변수는 아무 객체도 가리키지 않는다는 뜻의 null을 담을 수 있고, 기본형 변수는 null을 담을 수 없다.

이렇게 바꿔 보세요

  • 처음 설정으로 — 이름 age에 타입 int를 붙여 선언하고 20을 담습니다. 컴파일에 성공하고 21이 출력됩니다.
  • 타입 int를 지우면 — 컴파일러가 age가 무엇인지 몰라 선언하지 않은 이름이라는 오류가 납니다.
  • "스무 살"을 담으면 — int 변수에 글자를 담을 수 없다는 컴파일 오류가 납니다.
  • 값을 담지 않으면 — 변수는 만들어지지만, 값을 담기 전에 읽어서 컴파일 오류가 납니다.

처음 설정으로 실행하면

  1. 컴파일러가 main 안을 위에서부터 읽습니다. 먼저 int age = 20; 줄을 읽습니다. 이 줄은 세 부분입니다. int는 타입으로, 정수만 담는다는 뜻입니다. age는 이름입니다. 20은 담을 값입니다. 컴파일러는 "age라는 이름은 int 타입의 변수다"라고 기억합니다.
  2. 컴파일러가 담으려는 값을 확인합니다. 20은 정수이므로 정수만 담는 int 변수 age에 담을 수 있습니다.
  3. 컴파일러가 age = age + 1; 줄을 확인합니다. 오른쪽의 age + 1은 age에 담긴 값을 읽는 일입니다. age는 int로 선언돼 있고 앞 줄에서 값이 담겼으므로 읽을 수 있습니다. int에 1을 더한 결과도 정수이므로 다시 age에 담아도 됩니다.
  4. 컴파일러가 System.out.println(age); 줄을 확인합니다. age는 int 변수이고 값도 담겨 있으므로 읽어서 출력할 수 있습니다.
  5. 컴파일이 성공해 실행할 Main 클래스 파일이 만들어집니다. age가 int인지, 담는 값이 맞는지, 읽을 수 있는지는 실행할 때가 아니라 지금 컴파일러가 컴파일하면서 확인했습니다.
  6. java Main으로 실행합니다. main이 시작되고 int age = 20; 줄이 실행됩니다. age라는 이름표가 붙은 int 칸이 만들어지고, 그 칸에 20이 담깁니다.
  7. age = age + 1; 줄이 실행됩니다. 먼저 오른쪽의 age + 1을 계산합니다. age 칸에 든 20에 1을 더하면 21입니다. 이 값을 같은 age 칸에 담습니다. 칸은 그대로이고 안의 값만 20에서 21로 바뀝니다. 여기서 = 는 "같다"가 아니라 "오른쪽 계산 결과를 왼쪽 칸에 담는다"는 뜻입니다.
  8. System.out.println(age);가 실행됩니다. age 칸에 든 값을 읽어 화면에 21을 출력합니다.

실행 결과

  • 변수는 값을 저장해 두는 공간에 붙인 이름입니다. int age = 20;은 세 부분입니다. 타입 int(정수만 담는다는 뜻), 이름 age, 담을 값 20입니다. 컴파일러가 이 줄에서 "age는 int 변수"라고 기억하고, 그 뒤의 줄들이 이 기억에 맞는지 실행하기 전에 확인했습니다.
  • 실행하면 age 칸에 20이 담기고, age = age + 1;이 같은 칸의 값을 21로 바꾸고, 21이 출력됩니다. 변수는 이름과 칸이 그대로이고 안의 값만 바뀔 수 있습니다.

코드

public class Main {
    public static void main(String[] args) {
        // 선언: int 타입의 변수 age를 만들고 20을 담는다
        int age = 20;
        age = age + 1;
        System.out.println(age);
    }
}

이 모형의 전제

컴파일러와 실행 환경은 JDK 21.0.12.1(javac 21)입니다. 여섯 가지 조합을 모두, 화면의 코드와 같은 소스(줄 단위로 같은 글)를 javax.tools로 컴파일하고, 컴파일에 성공한 것은 클래스 파일을 새 클래스 로더로 읽어 Main.main을 실행해 표준 출력을 잡은 결과와 대조했습니다. 대조한 것은 컴파일 성공 여부, 첫 번째 오류의 진단 코드(compiler.err.cant.resolve.location, prob.found.req, var.might.not.have.been.initialized를 화면의 세 가지 오류 설명으로 옮겼습니다), 오류의 개수와 오류가 난 줄, Main 클래스 파일이 만들어졌는지, 실행했을 때의 출력입니다. 문서는 Java Language Specification(Java SE 21)을 직접 열어 확인했습니다. 모든 변수와 식에 컴파일할 때 알려진 타입이 있다는 것은 4장 서두, 변수가 값을 저장하는 공간이고 컴파일 시점의 타입을 가진다는 것은 4.12절, 기본형 변수는 그 타입의 값만 담는다는 것은 4.12.1절, int가 32비트 부호 있는 정수라는 것은 4.2절과 4.2.1절, 지역 변수 선언이 타입(또는 var)과 이름과 선택적인 초기화로 이루어진다는 것은 14.4절, 초기화 없이 선언한 변수는 읽기 전에 값을 담아야 하고 아니면 컴파일 오류라는 것은 14.4.2절과 4.12.5절과 16장 서두를 따랐습니다. 지역 변수에는 필드와 달리 기본값이 저절로 들어가지 않는다는 것도 4.12.5절입니다. 값을 읽는 것만 접근으로 치고 = 왼쪽의 이름은 접근이 아니라는 것은 16장 서두입니다. 오류의 종류, 개수, 어느 줄에서 나는지는 명세가 정한 것이 아니라 이 javac에서 관찰한 것입니다. 오류가 여럿이면 javac는 모두 알리는데, 표에는 첫 번째 것만 적었습니다. 컴파일에 실패한 모든 조합에서 Main 클래스 파일은 만들어지지 않았고, 그래서 실행할 수 없다고 적었습니다. 타입 int도 값도 없는 조합은 선언 줄을 아예 두지 않았습니다. 타입 없이 age;만 쓴 줄은 문법에 맞는 문장이 아니기 때문이며(14.8절: 문장으로 쓸 수 있는 식은 대입, 증감, 메서드 호출, 객체 생성뿐), 이 모양을 한 번 따로 컴파일해 보니 javac가 not a statement라는 문법 오류를 냈습니다(조합 대조에는 넣지 않았습니다). 이 실습은 지역 변수와 int 하나만 다뤘습니다. 다른 기본형, 참조형 변수, var, 변수의 이름 짓기와 범위, 상수(final)는 다루지 않았습니다. 기본형과 참조형 변수에 값이 어떻게 복사되는지는 "세부 동작 실습: 변수와 타입"에서 다룹니다.
