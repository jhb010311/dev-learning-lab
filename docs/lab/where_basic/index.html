WHERE

WHERE는 무엇을 정하고, 없으면 어떻게 되는가

왜 생겼나 — 테이블에는 행이 수천, 수만 개 쌓이지만 한 번에 필요한 것은 대개 그중 몇 행이다. WHERE가 없다면 모든 행을 프로그램으로 읽어 와서 필요한 행을 직접 골라야 하고, 한 사람의 정보만 고칠 방법도 없다. WHERE는 고르는 일을 DB에 맡겨, 필요한 행만 골라 다루게 한다.

지금 어디에 쓰나 — 로그인할 때 아이디로 회원 한 명을 찾거나, 한 사람의 비밀번호만 바꾸거나, 30일이 지난 기록만 지울 때처럼 특정 행만 다룰 때 붙인다. 실수로 WHERE를 빠뜨려 테이블 전체가 바뀌는 일을 막으려고, 먼저 같은 조건의 SELECT로 대상 행을 확인한 뒤 UPDATE나 DELETE를 실행하는 습관을 들이기도 한다.

WHERE는 SQL 문장 뒤에 붙이는 "WHERE 조건"입니다. UPDATE나 DELETE, SELECT를 테이블의 행 가운데 어느 행에 적용할지를 정합니다. DB는 행을 하나씩 보며 조건이 맞는지 확인하고, 맞는 행에만 문장을 적용하거나 읽어 옵니다. 이 실습은 문장의 종류와 WHERE의 조건을 바꿔 가며 같은 테이블에서 같은 SQL을 실행해, 몇 행에 문장이 적용되고 마지막에 어떤 행이 남는지를 봅니다. WHERE를 지우면 어떻게 되는지도 봅니다.

이 실습에 나오는 개념

WHERE 절
WHERE 절은 SELECT, UPDATE, DELETE 문 뒤에 붙여 테이블의 행 가운데 어느 행에 그 문장을 적용할지를 정하는 조건이다. DB는 행마다 조건이 참인지 확인하고, 참인 행에만 UPDATE나 DELETE를 적용하거나 SELECT로 읽어 온다. 조건에 맞는 행이 여럿이면 여럿 모두에 적용되고, 하나도 없으면 아무 행에도 적용되지 않으며 그것은 오류가 아니다. WHERE를 적지 않으면 모든 행이 대상이므로, SELECT는 전체를 읽고 UPDATE는 모든 행을 고치고 DELETE는 모든 행을 지운다.
UPDATE와 DELETE
지금 어디에 쓰나 — 회원 정보 고치기, 주문 상태 바꾸기, 탈퇴한 회원 지우기처럼 이미 있는 데이터를 바꾸거나 없앨 때 쓴다. 실제 서비스에서는 행을 지우는 대신 deleted 같은 열을 UPDATE로 바꿔 "지운 것"으로 표시해 두는 방법도 흔히 쓴다.
UPDATE는 테이블에 이미 있는 행의 열 값을 새 값으로 고치는 문장이고, DELETE는 행을 지우는 문장이다. 둘 다 어느 행에 적용할지를 WHERE 조건으로 정하며, 실행하면 적용된 행의 수를 돌려준다(JDBC에서는 executeUpdate가 그 수를 돌려준다). WHERE를 적지 않으면 UPDATE는 모든 행을 고치고 DELETE는 모든 행을 지운다. 이때도 문장은 오류 없이 끝나므로, 한 사람만 고치거나 지우려던 문장에서 WHERE를 빠뜨리면 DB가 알려 주지 않는다. DELETE로 행을 모두 지워도 테이블 자체는 남는다.
행과 열
왜 생겼나 — 정보를 건마다 제각각 적어 두면 어디에 무엇이 있는지 몰라 찾거나 비교하기 어렵다. 행과 열은 칸(열)의 이름과 타입을 먼저 정해 두고 정보 한 건을 그 칸들에 맞춰 한 줄(행)로 적게 해서, 모든 데이터를 같은 모양으로 맞춘다.
지금 어디에 쓰나 — 회원, 주문, 게시글처럼 같은 항목을 가진 정보가 여러 건 쌓이는 것을 저장할 때 쓴다. JPA를 쓰면 엔티티 클래스 하나가 테이블에, 그 필드가 열에, 객체 하나가 행 하나에 짝지어진다.
관계형 데이터베이스의 테이블은 표처럼 열과 행으로 이루어진다. 열(컬럼)은 테이블을 만들 때 이름과 타입을 정해 두는 칸의 종류이고, 예를 들어 member 테이블의 id, name이 열이다. 행(레코드)은 그 열들에 값을 채운 한 줄이며, 회원 한 사람의 정보가 행 하나가 된다. INSERT는 행을 하나 추가하고, UPDATE는 WHERE 조건에 맞는 행을 모두 고치며, SELECT는 행을 읽어 온다. 열에 값이 없는 것은 NULL로 나타낸다.

이렇게 바꿔 보세요

  • 처음 설정으로 — WHERE id = 2가 붙은 UPDATE. 조건에 맞는 id 2의 행만 바뀝니다.
  • WHERE를 지우면 — 조건이 없으면 모든 행이 대상이 되어, UPDATE가 세 행을 다 고칩니다.
  • 조건을 age = 30으로 바꾸면 — 맞는 행이 둘이면 둘 모두에 적용됩니다.
  • 맞는 행이 없는 조건이면 — 맞는 행이 없으면 아무 행도 바뀌지 않고, 오류도 아닙니다.
  • DELETE에서 WHERE를 지우면 — WHERE 없는 DELETE는 테이블의 모든 행을 지웁니다.

처음 설정으로 실행하면

  1. CREATE TABLE과 INSERT: DB가 member 테이블을 만들고 행 세 개(김철수, 이영희, 박민수)를 넣습니다. 테이블은 열(id, name, age)과 행(한 사람의 정보 한 줄)으로 이루어집니다. 아래 문장이 적용될 수 있는 행은 이 세 행이 전부입니다.
  2. UPDATE member SET name = '탈퇴' WHERE id = 2: 이 문장에는 WHERE 조건이 붙어 있습니다(WHERE id = 2). WHERE 뒤의 조건은 "어느 행에 이 문장을 적용할지"를 정합니다. DB는 member 테이블의 행을 하나씩 보며 id가 2인지 확인합니다. 이 확인을 하는 코드를 우리는 쓰지 않았습니다. DB가 문장마다 스스로 합니다.
  3. DB가 첫 번째 행(1, 김철수, 20)을 봅니다: id가 2인가? 이 행의 id는 1이고 2가 아니므로 "아니요"입니다. 조건에 맞지 않는 행이라 이 행에는 문장을 적용하지 않습니다.
  4. 두 번째 행(2, 이영희, 30): id가 2인가? 이 행의 id는 2이므로 "예"입니다. 조건에 맞는 행입니다.
  5. 세 번째 행(3, 박민수, 30): id가 2인가? 이 행의 id는 3이고 2가 아니므로 "아니요"입니다. 조건에 맞지 않는 행이라 문장을 적용하지 않습니다.
  6. UPDATE member SET name = '탈퇴' WHERE id = 2: 조건에 맞은 행(id 2)에만 문장을 적용합니다. DB가 그 행의 name을 탈퇴로 바꿉니다. 돌려주는 값(바뀐 행 수)은 1입니다. 맞지 않은 행(id 1, 3)은 그대로입니다.
  7. SELECT * FROM member ORDER BY id: 이 SELECT에는 WHERE가 없으므로 테이블에 남은 행을 모두 읽습니다. 결과는 (1, 김철수, 20), (2, 탈퇴, 30), (3, 박민수, 30)입니다. id 2인 행의 name만 탈퇴로 바뀌었고 나머지는 그대로입니다.

실행 결과

  • WHERE는 문장 뒤에 붙여 "어느 행에 이 문장을 적용할지" 정하는 조건입니다. "WHERE id = 2"를 붙인 UPDATE는 조건에 맞는 id 2의 행만 바꿨습니다.
  • DB는 행마다 조건이 맞는지 보고, 맞는 행에만 문장을 적용합니다. 나머지 두 행은 조건에 맞지 않아 그대로입니다.

코드

CREATE TABLE member (
    id   INT PRIMARY KEY,
    name VARCHAR(20),
    age  INT
);
INSERT INTO member VALUES (1, '김철수', 20);
INSERT INTO member VALUES (2, '이영희', 30);
INSERT INTO member VALUES (3, '박민수', 30);

-- WHERE: 조건에 맞는 행에만 이 문장을 적용한다
UPDATE member SET name = '탈퇴' WHERE id = 2;
SELECT * FROM member ORDER BY id;

이 모형의 전제

H2 2.4.240(메모리 DB, JDBC)에서 실행해 대조했습니다. 열두 가지 조합을 모두, 화면의 SQL 전체(주석 줄 포함)를 글자 그대로 한 문장씩 실행해서, 문장이 적용된 행의 수와 어느 행인지(UPDATE는 이름이 바뀐 행, DELETE는 사라진 행, SELECT는 읽힌 행), 오류가 났는지, 마지막 SELECT의 결과를 모형과 대조했습니다. 맞는 행이 없는 조건(WHERE id = 9)과 WHERE가 없는 UPDATE·DELETE가 H2에서 오류 없이 끝난다는 것, WHERE 없는 DELETE 뒤에도 테이블이 남아 마지막 SELECT가 빈 결과를 돌려준다는 것은 이 실행에서 확인했습니다. 규칙은 MySQL 8.4 문서의 UPDATE 문(15.2.17절: WHERE가 있으면 조건에 맞는 행만 고치고 없으면 모든 행을 고친다), DELETE 문(15.2.2절: WHERE가 없으면 모든 행을 지운다), SELECT 문(15.2.13절: WHERE가 없으면 모든 행을 선택한다)을 직접 열어 확인했습니다. 또 MySQL에는 WHERE를 잊은 UPDATE와 DELETE를 막는 safe-updates 모드가 있다는 것을 MySQL 문서(mysql 클라이언트 팁의 Using Safe-Updates Mode)에서 확인했습니다. 이 모드를 켜면 WHERE에 키 조건이 없는 UPDATE와 DELETE는 오류가 나는데, 이 실습은 그 모드를 다루지 않습니다. MySQL에서의 실행 대조는 하지 않았습니다. 그래서 위 규칙은 문서와 H2 실행이 일치한다는 근거이고, MySQL이 같은 SQL에서 같은 결과를 내는지는 실행으로 확인하지 않았습니다. 화면은 DB가 행을 하나씩 보며 조건을 확인하는 모습으로 그렸습니다. 실제 DB는 인덱스를 쓰는 등 구현에 따라 다른 방법으로 맞는 행을 찾을 수 있으며, 실행으로 확인한 것은 어느 행에 문장이 적용되었는가이지 확인 순서가 아닙니다. 문장이 돌려주는 "적용된 행 수"는 이 실습의 UPDATE에서 맞은 행의 이름이 모두 이전과 달라 맞은 행 수와 바뀐 행 수가 같았습니다. 새 값이 이미 같은 행을 DB가 어떻게 세는지는 DB와 드라이버 설정에 따라 다를 수 있어 다루지 않았습니다. 조건은 같음(=) 비교 하나만 다루며, AND·OR, 범위, LIKE, NULL 비교는 다루지 않습니다.
