스택·큐·우선순위 큐

넣은 순서와 꺼내는 순서

왜 생겼나 — 값을 리스트 하나에 모아 두고 꺼낼 때마다 어느 것을 꺼낼지 직접 찾으면, 꺼내는 규칙이 코드 곳곳에 흩어지고 가장 작은 값을 찾을 때는 매번 전체를 훑어야 한다. 스택·큐·우선순위 큐는 꺼내는 순서를 자료구조가 정해, 나중 것부터·먼저 것부터·가장 작은 것부터 꺼내는 일을 메서드 하나로 끝내게 한다. 우선순위 큐는 힙을 써서 넣고 뺄 때 전체를 다시 정렬하지 않는다.

지금 어디에 쓰나 — 스택은 되돌리기 기록, 괄호 짝 검사, 깊이 우선 탐색에, 큐는 들어온 순서대로 처리할 작업 대기열과 너비 우선 탐색에 쓴다. 우선순위 큐는 마감이 가까운 작업부터 처리하거나, 상위 N개를 고르거나, 최단 경로(다익스트라)를 구할 때 쓴다. 여러 스레드가 함께 넣고 빼는 대기열에는 LinkedBlockingQueue 같은 BlockingQueue 구현을 쓴다.

같은 숫자 다섯 개를 같은 순서로 넣어도, 자료구조에 따라 꺼내지는 순서가 다릅니다. 스택은 나중에 넣은 것부터, 큐는 먼저 넣은 것부터, 우선순위 큐는 가장 작은 것부터 나옵니다.

실행으로 대조 · JDK 21의 실제 ArrayDeque·PriorityQueue와 대조

이 실습에 나오는 개념

스택, 큐, 덱
스택은 나중에 넣은 것을 먼저 꺼내는(LIFO) 구조, 큐는 먼저 넣은 것을 먼저 꺼내는(FIFO) 구조, 덱은 양쪽 끝에서 넣고 뺄 수 있는 구조다. 자바에서는 스택과 큐 모두 ArrayDeque로 구현하는 것이 권장된다.
힙과 우선순위 큐
왜 생겼나 — 우선순위대로 꺼낼 값을 정렬된 배열로 두면 넣을 때마다 뒤 원소를 밀어야 해서 O(n)이 들고, 정렬 없이 두면 꺼낼 때마다 O(n)이 든다. 힙은 전체를 정렬하지 않고 부모가 자식보다 앞선다는 순서만 지켜, 넣기와 꺼내기를 모두 O(log n)으로 맞춘다.
지금 어디에 쓰나 — 실행 시각이 가장 이른 예약 작업을 고르는 스케줄러(자바의 ScheduledThreadPoolExecutor도 힙을 쓴다)나, 정렬된 목록 여러 개를 하나로 합치는 일에 쓴다. 맨 앞 하나가 아니라 전체를 순서대로 훑거나 중간의 값을 지워야 하면 TreeSet이나 TreeMap이 낫다.
힙은 부모 노드가 자식 노드보다 항상 작거나 같은(최소 힙), 또는 크거나 같은(최대 힙) 완전 이진 트리다. 가장 작은(큰) 값을 O(1)에 확인하고 O(log n)에 꺼낼 수 있어 우선순위 큐를 구현하는 데 쓰인다. 자바의 PriorityQueue가 힙으로 구현되어 있다. JVM의 메모리 영역인 힙과는 이름만 같다.
시간 복잡도(Big-O)
왜 생겼나 — 실행 시간을 초로 재면 컴퓨터와 입력에 따라 값이 달라서, 두 방식 중 어느 쪽이 나은지 말하기 어렵다. Big-O 표기는 상수와 작은 항을 버리고 입력이 커질 때 늘어나는 모양만 남겨, 환경과 관계없이 방식끼리 비교하게 한다.
지금 어디에 쓰나 — 자료구조를 고를 때(ArrayList의 contains는 O(n), HashSet은 평균 O(1)), 이중 반복문이 데이터 증가를 버틸지 따질 때, 코딩 테스트에서 풀이가 시간 안에 끝날지 가늠할 때 쓴다.
입력 크기 n이 커질 때 알고리즘의 연산 횟수가 얼마나 빠르게 늘어나는지를 나타내는 표기다. O(1)은 크기와 무관하게 일정, O(log n)은 크기가 두 배가 되어도 한 단계만 늘어남, O(n)은 크기에 비례, O(n²)은 크기의 제곱에 비례함을 뜻한다. 데이터가 많아질 때 어떤 방식이 버티는지 판단하는 기준이다.

이렇게 바꿔 보세요

  • 처음 설정으로 — 우선순위 큐. 넣은 순서와 상관없이 작은 것부터 나옵니다.
  • 스택 — 마지막에 넣은 9가 가장 먼저 나옵니다.
  • 큐 — 넣은 순서 그대로 나옵니다.
  • 우선순위 큐에 내림차순으로 — 넣을 때마다 새 값이 맨 위까지 올라갑니다.

처음 설정으로 실행하면

  1. offer(5): 배열 맨 끝에 넣은 뒤, 부모보다 작으면 자리를 바꾸며 위로 올라갑니다. 첫 값이라 맨 위에 그대로 놓입니다.
  2. offer(2): 배열 맨 끝에 넣은 뒤, 부모보다 작으면 자리를 바꾸며 위로 올라갑니다. 1번 올라가 맨 위(가장 작은 값의 자리)에 도착했습니다.
  3. offer(8): 배열 맨 끝에 넣은 뒤, 부모보다 작으면 자리를 바꾸며 위로 올라갑니다. 부모보다 작지 않아 그 자리에 머뭅니다.
  4. offer(1): 배열 맨 끝에 넣은 뒤, 부모보다 작으면 자리를 바꾸며 위로 올라갑니다. 2번 올라가 맨 위(가장 작은 값의 자리)에 도착했습니다.
  5. offer(9): 배열 맨 끝에 넣은 뒤, 부모보다 작으면 자리를 바꾸며 위로 올라갑니다. 부모보다 작지 않아 그 자리에 머뭅니다.
  6. poll(): 맨 위의 가장 작은 값(1)을 꺼냅니다. 빈 맨 위에 배열의 마지막 값을 올린 뒤, 두 자식 중 작은 쪽과 자리를 바꾸며 내려갑니다(2번 내려감).
  7. poll(): 맨 위의 가장 작은 값(2)을 꺼냅니다. 빈 맨 위에 배열의 마지막 값을 올린 뒤, 두 자식 중 작은 쪽과 자리를 바꾸며 내려갑니다(1번 내려감).
  8. poll(): 맨 위의 가장 작은 값(5)을 꺼냅니다. 남은 값이 있으면 배열의 마지막 값이 빈 맨 위로 올라옵니다. 이번에는 자리를 바꿀 일이 없었습니다.
  9. poll(): 맨 위의 가장 작은 값(8)을 꺼냅니다. 남은 값이 있으면 배열의 마지막 값이 빈 맨 위로 올라옵니다. 이번에는 자리를 바꿀 일이 없었습니다.
  10. poll(): 맨 위의 가장 작은 값(9)을 꺼냅니다. 남은 값이 있으면 배열의 마지막 값이 빈 맨 위로 올라옵니다. 이번에는 자리를 바꿀 일이 없었습니다.

실행 결과

  • 우선순위 큐는 넣은 순서와 무관하게 가장 작은 값이 먼저 나옵니다. 내부 배열은 완전히 정렬돼 있지 않고, "부모는 자식보다 작거나 같다"는 조건만 지킵니다(힙). 그래서 맨 위가 항상 최솟값입니다.
  • 넣기와 꺼내기는 트리의 높이만큼만 자리를 바꾸므로 O(log n)입니다. 전체를 매번 정렬하는 것보다 훨씬 쌉니다. 작업 스케줄링, 상위 N개 구하기, 최단 경로 알고리즘에 씁니다.

코드

// main 메서드 안의 줄만 보임 (클래스·main 선언과 import는 생략)
PriorityQueue<Integer> pq = new PriorityQueue<>();   // 작은 값이 먼저
for (int x : List.of(5, 2, 8, 1, 9)) pq.offer(x);

while (!pq.isEmpty()) System.out.print(pq.poll() + " ");

이 모형의 전제

꺼낸 순서와 우선순위 큐 내부 배열의 변화는 검증 환경의 JDK 21에서 실제 ArrayDeque와 PriorityQueue를 실행해 대조했습니다(내부 배열은 넣을 때마다, 꺼낼 때마다 모두 일치). PriorityQueue는 기본적으로 작은 값이 먼저 나오며, Comparator를 주면 기준을 바꿀 수 있습니다.
