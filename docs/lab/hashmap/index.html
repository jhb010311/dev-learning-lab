HashMap 내부

HashMap은 키를 어디에 넣고 어떻게 찾나

키의 hashCode로 버킷 번호를 정해 넣습니다. hashCode가 겹치면 한 버킷에 줄줄이 달리고, 항목이 많아지면 버킷을 두 배로 늘립니다.

실행으로 대조 · JDK 21의 실제 HashMap 내부와 360단계 대조

이 실습에 나오는 개념

해시 테이블과 HashMap
키를 해시 함수에 넣어 나온 값으로 저장 위치(버킷)를 정하는 자료구조다. 키만 알면 위치를 바로 계산할 수 있어 조회, 삽입, 삭제가 평균 O(1)이다. 자바의 HashMap이 이 구조이며, 순서를 보장하지 않고 스레드 안전하지 않다.
해시 충돌
서로 다른 키가 같은 버킷에 배정되는 현상이다. 버킷 수는 유한하므로 피할 수 없다. 자바의 HashMap은 같은 버킷의 엔트리들을 연결 리스트로 이어 두고, 한 버킷에 너무 많이 몰리면 레드-블랙 트리로 바꿔 탐색 시간을 줄인다. 충돌이 많을수록 성능이 떨어지므로 hashCode가 값을 고르게 분산해야 한다.
로드 팩터와 리사이즈
로드 팩터는 해시 테이블이 얼마나 찼을 때 크기를 늘릴지 정하는 비율이다. HashMap의 기본값은 0.75로, 저장된 엔트리 수가 버킷 수의 75%를 넘으면 버킷 수를 두 배로 늘리고 엔트리들을 다시 배치한다(리사이즈). 리사이즈는 비용이 크므로 넣을 양을 알면 초기 용량을 미리 지정하는 것이 좋다.
레드-블랙 트리
스스로 균형을 맞추는 이진 탐색 트리의 한 종류다. 삽입과 삭제 때마다 규칙에 따라 구조를 조정해 한쪽으로 치우치지 않게 하므로 조회, 삽입, 삭제가 항상 O(log n)이다. 자바의 TreeMap과 TreeSet, 그리고 충돌이 많은 HashMap 버킷에 쓰인다.
equals와 hashCode 규약
equals()로 같다고 판단되는 두 객체는 반드시 같은 hashCode() 값을 반환해야 한다는 규칙이다. HashMap이나 HashSet은 먼저 해시 값으로 저장 위치를 찾고 그 안에서 equals로 비교하기 때문에, equals만 재정의하면 내용이 같은 객체를 찾지 못한다. 따라서 두 메서드는 항상 같은 필드를 기준으로 함께 재정의한다.

실행 결과

  • equals와 hashCode를 둘 다 재정의해서, 같은 id로 만든 새 객체로도 값을 바꾸고 찾을 수 있었습니다.

코드

class MemberKey {
    final int id;
    MemberKey(int id) { this.id = id; }

    @Override public boolean equals(Object o) {
        return o instanceof MemberKey k && k.id == id;
    }

    @Override public int hashCode() {
        return Integer.hashCode(id);   // id 그대로
    }
}

Map<MemberKey, String> map = new HashMap<>(16, 0.75f);
for (int id : ids) {                 // id 13개
    map.put(new MemberKey(id), "회원");
}

// 처음 넣은 것과 같은 id로 새 객체를 만들어서
map.put(new MemberKey(ids[0]), "수정");
map.get(new MemberKey(ids[0]));

이 모형의 전제

초기 버킷 수는 16개로 고정했습니다. 버킷 번호 계산(해시의 위쪽 16비트를 아래쪽에 섞은 뒤 버킷 수로 나눈 나머지), 늘리는 기준(저장 개수 > 버킷 수 × 로드 팩터), 한 버킷에 9번째 노드가 달릴 때 버킷 수가 64개 미만이면 늘리고 64개 이상이면 트리로 바꾸는 규칙은 JDK HashMap 구현과 같습니다. 이 PC의 JDK 21에서 실제 HashMap 내부를 꺼내 본 결과와 대조했고, hashCode 세 가지 × 로드 팩터 세 가지로 40개씩 넣은 360단계 모두에서 버킷 수, 버킷별 개수, 트리 여부가 일치했습니다. hashCode를 재정의하지 않았을 때의 값은 실제로는 JVM이 객체마다 정하는 값이며, 여기서는 임의의 수로 대신했습니다.
