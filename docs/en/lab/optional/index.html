Optional

Why does the default-value code in orElse run even when a value is present?

Why it exists — With a method that returns null, you cannot tell from the return type alone that a value may be missing, so if the caller forgets the null check, a NullPointerException occurred on some other line much later. Optional shows "may be absent" in the return type, and lets you write the default value or the handling to use when the value is absent right where you take the value out, with methods such as orElse and map.

Where it's used today — It is used as the return type of methods whose lookup result may be absent. findById of Spring Data JPA and findFirst and max of streams are typical examples that return an Optional. It is generally not used as the type of a field or a method parameter, and a method with several results returns an empty list instead of an Optional.

An Optional is an object that expresses that a value may or may not be present. When a value is present, the Optional refers to it; otherwise the Optional is empty. Depending on how you create it (of, ofNullable, empty) and how you get the value out (get, orElse, orElseGet, map), a missing value leads either to an exception or to a default value being used. orElse and orElseGet look as if they give the same result, but they differ in when the code that creates the default value runs.

Checked against real execution · All 24 combinations were run on JDK 21, and the output and the exceptions were checked against the results

Concepts in this lab

Optional
This container class expresses in the type that a value may or may not be present. When a method returns it in place of null, the caller is guided to handle the case where there is no value. It is used mainly as a method return type.
orElse and orElseGet
Why it exists — If every time you take a value out of an Optional you write an if statement that checks with isPresent() and then calls get(), the code gets long, and mistakes also happen, such as calling get() without checking. orElse and orElseGet let you write "if it is empty, this" in a single call.
Where it's used today — Use orElse where a fixed default value is used when the setting value is missing, and orElseGet where the DB has to be queried again or a new object has to be created and saved when it is empty. To throw an exception instead of a default value when it is empty, use orElseThrow.
These are the two methods that set the default value to use in its place when an Optional is empty. orElse(value) takes the default value itself as its argument, and orElseGet(function) takes a function (a lambda expression) that produces the default value. Java evaluates the arguments before it calls a method, so if you write orElse(makeDefault()), makeDefault() runs even when the Optional has a value. orElseGet runs the function that it was given only when the Optional is empty. So use orElseGet when creating the default value takes time or when other work, such as saving or logging, happens along with it.
NullPointerException
This exception is thrown when code tries to call a method or read a field through a reference that is null. null means that there is no object that the reference refers to, and an object that does not exist cannot be asked to do anything, so the exception is thrown. Whether a value is null depends on the values at run time, so the compiler cannot catch it in advance and it shows up only when the code runs (it is an unchecked exception, so handling is not forced either). This exception is also thrown when null is passed to a method that is written not to accept null (such as Optional.of or Objects.requireNonNull). In places where a value may be absent, you make this exception less likely by checking for null first or by using Optional to show in the type that the value may be absent.
Lazy evaluation
Why it exists — If a computation is done immediately, it produces values that end up unused, and every step must store its whole intermediate result. Lazy evaluation removes that waste by delaying the computation until the value is actually used.
Where it's used today — Optional's orElseGet runs the Supplier only when there is no value, and the Logger of java.util.logging, when given a Supplier, does not build the message string if logging at that level is turned off.
This approach delays a computation until its result is actually needed. The intermediate operations of a stream do not run as soon as they are called. They run only when the terminal operation is called, and each element passes through the pipeline one at a time. The stream can process only as much as it needs and then stop. Lazy fetching in JPA follows the same idea: associated data is queried when it is actually used.
Lambda expression
This is a syntax, introduced in Java 8, for writing a function with no name in a compact way. It has the form (parameters) -> body, and it is used as the implementation of a functional interface, which has only one abstract method. It lets you pass behavior (code) to another method as if it were a value.

Try these

  • Default settings — makeDefault() runs even though a value is present.
  • Switching to orElseGet — When a value is present, makeDefault() does not run.
  • Passing null to Optional.of — A NullPointerException is thrown at the moment the Optional is created.
  • get() on an empty Optional — The result is not null but a NoSuchElementException.
  • orElseGet on an empty Optional — Only in this case does makeDefault() run.
  • Chaining map (no value) — The code runs to the end without an exception, with no null check.
  • Chaining map (value present) — The functions are applied to the value one after another.

Running with the default settings

  1. String name = "kim": name refers to the string "kim".
  2. Optional.ofNullable(name): name is not null, so this creates an Optional that refers to the value "kim".
  3. System.out.println(opt): This prints one line, Optional[kim]. The value that opt refers to is shown inside the square brackets.
  4. makeDefault(): Before orElse is called, the argument in the parentheses is evaluated first, because Java works out the values to pass before it calls a method. Whether or not opt has a value, makeDefault() runs, "makeDefault ran" is printed, and "guest" is created.
  5. opt.orElse("guest"): A value is present, so orElse returns "kim". The "guest" that was just created is not used and is discarded.
  6. System.out.println(result): This prints one line, kim.

Result of this run

  • A value is present, so no default value is needed, and yet makeDefault() ran. What is inside the parentheses of orElse is an ordinary argument, so it is always evaluated before orElse is called.
  • When the default value is a value that already exists, such as "none", orElse is enough. When creating the default value involves work such as a database query or creating an object, use orElseGet.

Code

import java.util.Optional;

public class Main {
    static String makeDefault() {                // method that creates the default value
        System.out.println("makeDefault ran");
        return "guest";
    }

    public static void main(String[] args) {
        String name = "kim";
        Optional<String> opt = Optional.ofNullable(name);
        System.out.println(opt);

        String result = opt.orElse(makeDefault());
        System.out.println(result);
    }
}

Assumptions of this model

For the 24 combinations (Optional.empty() does not use name, so there are 20 distinct cases), the printed lines and the exceptions were checked against the results of running the same code on JDK 21 in our test environment. Whether makeDefault() ran was confirmed by whether the line that the method prints appears in the output. That map does not run the function when the Optional is empty is behavior stated in the documentation of Optional, and in execution it was confirmed by "no name" being printed without an exception. The exception message "No value present" is as of JDK 21. The NullPointerException from Optional.of(null) has no message.
