# 한국어 글 검수 안내

공개된 학습 사이트의 글을 검수합니다. 한국어가 모국어인 개발자가 읽다가 "이게 무슨 말이냐"고 할 문장, 틀린 조사, 오타가 하나도 남지 않게 하는 것이 목적입니다. 이런 것이 하나만 보여도 사이트 전체가 대충 만든 것으로 보입니다.

**파일을 고치지 마세요.** 고칠 곳을 JSON 파일 하나에 적어 내는 것이 일의 전부입니다. 적용은 다른 사람이 합니다.

## 읽는 파일

실습 파일(`src/lessons/*.js`)은 자바스크립트입니다. 화면에 나오는 글은 작은따옴표로 싼 문자열 안에 있습니다. 문장이 변수와 이어 붙여져 있는 곳이 많습니다.

```js
push('요청 ' + i + ' 도착. 스레드 ' + busy + '개가 모두 일하는 중입니다.');
```

화면에는 `요청 3 도착. 스레드 2개가 모두 일하는 중입니다.`처럼 나옵니다. 문자열 조각만 보지 말고 이어 붙인 결과를 머릿속으로 만들어 읽으세요. `c.x === 'a' ? '…' : '…'`처럼 갈라지는 곳은 갈래마다 읽습니다.

글이 있는 곳: `nav`(이름), `title`(물음), `intro`(소개), `controls`의 `label`과 `options`, `presets`의 `t`·`q`·`d`, `columns`, `simulate` 안의 단계 설명(`push(...)`, `s: ...`)과 실행 결과(`sum.push(...)`), `render`와 `draw` 안의 표 제목·그림 글자, `assume`(전제), `code`의 주석.

## 찾을 것

1. **문법이 틀린 문장.** 주어와 서술어가 호응하지 않음, 목적어가 겹침, 문장이 끝나지 않고 끊김, 같은 말이 겹침.
2. **말이 안 되거나 사람이 그렇게 말하지 않는 문장.** 설정 이름이나 선택지 이름을 그대로 끼워 넣어 어색한 문장("실행 방식을 두 문장을 트랜잭션으로 묶음 쪽으로 바꾸면"), 무엇을 가리키는지 알 수 없는 "그것", "이 값".
3. **조사가 틀린 곳.** 받침에 맞지 않는 을/를, 이/가, 은/는, 과/와, 으로/로. 특히 **변수 뒤에 붙은 조사**를 보세요. `name + '를 저장합니다'`에서 `name`이 "주문"일 수도 "회원"일 수도 있으면 한쪽은 틀립니다. 숫자 뒤도 같습니다(`n + '을'`: 2을, 4을은 틀림).
4. **오타, 띄어쓰기, 문장 부호.** 틀린 글자, 붙여 써야 할 것을 띄었거나 그 반대, 마침표가 두 번 찍힘, 괄호가 닫히지 않음.
5. **글과 글이 서로 다른 말을 하는 곳.** 같은 파일 안에서 한 문장은 "두 번"이라 하고 다른 문장은 "세 번"이라 하는 식. 이것은 고치지 말고 보고만 합니다(아래 `report`).

## 고치지 않는 것

- 뜻, 숫자, 코드 이름(클래스·메서드·애너테이션·SQL), 기술 용어.
- 말투와 표현 취향. "~합니다"체, 문장 길이, 낱말 선택은 틀리지 않았으면 그대로 둡니다. 더 좋아 보이는 표현으로 바꾸는 일이 아닙니다.
- 코드. 문자열 밖의 것은 건드리지 않습니다.
- `assume`(전제)에 있는 "이 PC에서 실행해 대조했습니다" 같은 검증 기록은 그대로 둡니다.

확신이 서지 않는 것은 고치지 말고 `report`에 적으세요.

## 결과 파일 형식

```json
{
  "fix": [
    { "file": "00_threadpool.js", "old": "원래 글자", "new": "고친 글자", "why": "무엇이 틀렸는지 한 줄" }
  ],
  "code": [
    { "file": "00_threadpool.js", "line": 40, "what": "th.id + '이': 스레드 번호가 2, 4, 5, 9로 끝나면 '가'여야 함" }
  ],
  "report": [
    { "file": "00_threadpool.js", "what": "소개는 요청이 10개라 하고 단계 설명은 12개라 함" }
  ]
}
```

- `fix`: 글자만 바꾸면 되는 것. **`old`는 그 파일에 정확히 한 번만 나오는 글자열**이어야 하고, **한 문자열 조각 안**에서 골라야 합니다(따옴표나 `+`를 걸치지 않습니다). 한 번만 나오게 하려면 앞뒤 글자를 넉넉히 넣으세요. `old`와 `new`에는 작은따옴표('), 역슬래시(\), 줄바꿈을 넣지 않습니다. 원문에 `\'`가 들어 있는 조각은 `fix`로 고치지 말고 `code`에 적으세요.
- `code`: 코드를 고쳐야 하는 것(변수 뒤의 조사처럼 값에 따라 달라져야 하는 경우). 줄 번호와 무엇이 문제인지 적습니다.
- `report`: 고치지 않고 알리기만 할 것(글끼리 어긋남, 사실이 의심스러움, 확신이 없는 것).
- 고칠 것이 없으면 세 목록을 빈 배열로 둡니다.

저장한 뒤 node로 JSON이 열리는지, `fix`의 `old`가 각 파일에 정확히 한 번 나오는지 확인하세요.

```
node -e "const fs=require('fs');const r=JSON.parse(fs.readFileSync(process.argv[1],'utf8'));r.fix.forEach(x=>{const s=fs.readFileSync(process.argv[2]+'/'+x.file,'utf8');const n=s.split(x.old).length-1;if(n!==1)console.log(n+'번: '+x.file+' '+x.old)});console.log('fix '+r.fix.length+', code '+r.code.length+', report '+r.report.length)" <결과 파일> <읽은 폴더>
```
