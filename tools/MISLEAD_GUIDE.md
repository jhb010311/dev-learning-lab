# 오해를 부르는 표현 점검 안내

공개된 개발 학습 사이트의 글과 그림 글자를 읽고, **읽는 사람이 틀린 그림을 머릿속에 그리게 만드는 표현**을 찾습니다. 문장이 매끄러운지, 조사가 맞는지는 이미 따로 봤습니다. 이번에는 보지 않습니다.

**파일을 고치지 마세요.** 찾은 것을 JSON 파일 하나에 적어 내는 것이 일의 전부입니다. 고칠지 말지는 다른 사람이 근거를 확인한 뒤 정합니다.

## 발단이 된 예

"AOP와 프록시" 실습의 그림에 `진짜 OrderService — 프록시 안에 들어 있음`이라고 적혀 있었습니다. 실제로는 프록시 객체와 진짜 객체가 서로 다른 두 객체이고, 프록시가 진짜 객체를 **참조로 갖고 있을** 뿐입니다(실행해 보면 두 객체는 같지 않다고 나옵니다). "안에 들어 있다"는 비유로는 통하지만, 배우는 사람은 "객체 하나가 다른 객체를 품고 있다"거나 "상속했으니 부모 부분이 안에 들어 있다"로 이해하게 됩니다. 같은 그림에서 빈이 아닌 진짜 객체가 "스프링이 보관하는 객체(빈)" 테두리 안에 그려져 있던 것도 같은 문제였습니다.

이런 것을 찾습니다. **틀린 말은 아닌 것 같은데, 그대로 믿으면 틀린 지식이 되는 표현.**

## 읽는 파일

실습 파일(`src/lessons/*.js`)은 자바스크립트이고, 화면에 나오는 글은 문자열 안에 있습니다. 문자열이 변수와 이어 붙여진 곳은 이어 붙인 결과를 머릿속으로 만들어 읽습니다.

글이 있는 곳: `title`, `intro`, `controls`의 `label`·`options`·`hint`, `presets`의 `t`·`q`·`d`, `columns`, `simulate` 안의 단계 설명(`push(...)`)과 실행 결과(`sum.push(...)`), `render`의 표 제목과 칸 글자, **`draw` 안의 그림 글자**(`P.box`의 `title`·`sub`, `P.region`의 제목, `P.arrow`의 `label`, `P.note`), `code`의 주석, `assume`.

그림은 글자뿐 아니라 **배치**도 봅니다. `P.region(이름, x, y, w, h, 제목)`은 점선 테두리이고 그 좌표 안에 놓인 `P.box`는 "그 테두리에 속한 것"으로 보입니다. `P.arrow(이름, 출발, 도착, …)`는 방향이 뜻을 가집니다.

`assume`에는 "이 PC에서 무엇을 실행해 대조했다"는 기록이 있는 경우가 많습니다. 이 기록과 글이 어긋나면 중요한 단서입니다.

## 찾을 것

1. **들어 있다 / 감싼다 / 담는다 / 품는다 같은 포함 비유**가 실제 관계(참조, 상속, 위임, 대응)와 다른 곳. 객체가 객체를 "담고" 있다고 하지만 참조일 뿐인 것, 변수에 객체가 "들어 있다"고 하면서 참조라는 말이 그 실습 어디에도 없는 것 등.
2. **서로 다른 것을 같은 것처럼 부르는 곳.** 클래스와 객체, 변수와 객체, 참조와 값, 선언 타입과 실제 타입, 프로세스와 스레드, 연결과 요청, 쿠키와 세션, 인증과 인가, 암호화·해시·인코딩, 동시성과 병렬, 엔티티 객체와 테이블 행, 트랜잭션과 락, 컴파일 시점과 실행 시점, URL·경로·도메인.
3. **하는 주체가 틀린 곳.** 컴파일러가 하는 일을 JVM이 한다고, 브라우저가 하는 일을 서버가 한다고, 스프링이나 하이버네이트가 하는 일을 자바나 DB가 한다고(또는 그 반대로) 쓴 것.
4. **시점이 틀린 곳.** "save()를 부르면 INSERT가 나간다"처럼 실제로는 나중에(플러시, 커밋, 첫 사용 때) 일어나는 일을 그 줄에서 일어나는 것처럼 쓴 것. 또는 그 반대.
5. **복사 / 이동 / 저장 / 삭제 같은 물리 표현**이 실제와 다른 곳. 참조만 넘기는데 "복사된다", 표시만 하는데 "지워진다", 메모리에만 있는데 "저장된다".
6. **지나친 단정.** "항상", "절대", "반드시", "모든", "~만", "~할 수 없다", "~하면 안 된다"가 흔한 예외를 가리는 곳. 이 실습의 모형에서만 참인 것을 일반 법칙처럼 쓴 곳(모형의 숫자, 특정 DB·특정 버전의 동작).
7. **그림의 배치·화살표·이름표가 관계를 잘못 암시하는 곳.** 속하지 않는 것이 테두리 안에 있음, 화살표 방향이 호출·참조·데이터 흐름의 실제 방향과 반대, 같은 것을 두 상자로 또는 다른 것을 한 상자로 그림.
8. **원인과 결과가 뒤바뀐 곳**, 또는 "~때문에"로 이은 이유가 실제 이유가 아닌 곳.
9. **용어를 그 분야의 뜻과 다르게 쓴 곳.** 공식 문서나 표준 교재가 쓰는 뜻과 다르게 정의하거나, 정의 없이 다른 뜻으로 쓴 것.

## 찾지 않는 것

- 말투, 문장 길이, 낱말 취향, 조사, 띄어쓰기.
- **공식 문서도 쓰는 통상적인 단순화**로서 그 실습 안에서 정확한 관계가 함께 설명돼 있는 것. 예: "프록시가 대상 객체를 감싼다"는 스프링 문서도 쓰는 말입니다. 같은 실습에 "프록시가 진짜 객체를 참조로 갖고 있다"가 분명히 나오면 적지 않습니다. 정확한 설명이 어디에도 없이 비유만 있으면 적습니다.
- 실습이 스스로 "이 모형에서는", "여기서는"이라고 범위를 밝힌 단순화.
- 확신이 없는 사실 다툼. 다만 "틀렸을 가능성이 높은데 확인이 필요하다"는 것은 `confidence: "low"`로 적습니다.

파일 하나에서 나올 것은 보통 0~4개입니다. 억지로 채우지 마세요. 반대로, 분명한 것은 빠뜨리지 마세요.

## 결과 파일 형식

```json
{
  "found": [
    {
      "file": "252_aop_basic.js",
      "line": 117,
      "quote": "프록시 안에 들어 있음",
      "kind": 1,
      "misread": "프록시 객체가 진짜 객체를 품고 있거나, 상속한 부모 부분이 안에 들어 있다고 이해하게 됨",
      "truth": "프록시와 진짜 객체는 서로 다른 객체이고 프록시가 참조로 갖고 있음",
      "suggest": "프록시와 다른 객체 (프록시가 참조로 가짐)",
      "basis": "스프링 레퍼런스 Core > AOP > Understanding AOP Proxies. 이 실습 assume의 실행 기록에도 두 객체가 다르다고 나옴",
      "confidence": "high"
    }
  ],
  "read": ["252_aop_basic.js"]
}
```

- `quote`: 문제의 글자를 원문 그대로. **한 문자열 조각 안에서** 고르고(따옴표나 `+`를 걸치지 않음), 그 파일에서 찾을 수 있어야 합니다. 작은따옴표·역슬래시·줄바꿈은 넣지 않습니다.
- `kind`: 위 "찾을 것"의 번호.
- `misread`: 읽는 사람이 어떻게 잘못 이해하게 되는지.
- `truth`: 실제로는 어떤지.
- `suggest`: 고친다면 어떤 글이 좋은지. 길이는 원문과 비슷하게(그림 글자는 상자에 들어가야 합니다).
- `basis`: 근거. 공식 문서·명세의 이름과 장/절, 또는 그 파일 `assume`의 실행 기록. 근거를 댈 수 없으면 "확인 필요"라고 적습니다. **지어내지 마세요.**
- `confidence`: `high`(실제 동작과 분명히 다름) / `mid`(오해할 여지가 큼) / `low`(틀렸을 수 있어 확인 필요).
- `read`: 끝까지 읽은 파일 이름 전부. 읽지 못한 파일은 넣지 않습니다.

저장한 뒤 JSON이 열리는지 확인하세요.

```
node -e "const r=JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'));console.log('found '+r.found.length+', read '+r.read.length)" <결과 파일>
```
