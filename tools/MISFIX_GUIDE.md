# 오해 표현 고침 안내 (고치는 쪽)

점검에서 나온 것 가운데 **받아들이기로 정해진 항목**을 실제 고침으로 만드는 일입니다. 무엇을 고칠지는 이미 정해져 있습니다. 새로 찾아서 고치지 않습니다.

## 하는 일

1. 점검 결과 파일 `dist/audit/mis/m_<N>.json`의 `found`에서, 지시받은 번호(1부터 셈)의 항목만 봅니다.
2. 항목마다 **한국어 실습 파일**(`src/lessons/<파일>`)과 **영어 실습 파일**(`src/en/lessons/<같은 파일 이름>`)을 열어, 고칠 글자를 정합니다.
3. 고침을 `dist/audit/mis/cf_<NN>.json`(NN은 두 자리, 예: cf_06.json)에 적습니다. **실습 파일을 직접 편집하지 않습니다.**
4. `node tools/mis_apply_code.js`로 적용하고, 고친 실습마다 `node tools/i18n/check_en.js <실습 id>`를 돌려 통과하는지 봅니다(id는 실습 파일 맨 위 `id: '...'`).
5. 무엇을 고쳤고 무엇을 못 고쳤는지 보고합니다.

작업 폴더는 `E:\dev\dev-learning-lab` 입니다. 명령은 그 폴더에서 실행합니다.

## cf 파일 형식

```json
[
  { "file": "lessons/10_pc.js", "a": "원래 글자", "b": "고친 글자", "why": "왜 고치는지 한 줄" },
  { "file": "en/lessons/10_pc.js", "a": "original text", "b": "fixed text", "why": "위와 같음" }
]
```

- `file`: `src` 아래 경로. 한국어는 `lessons/…`, 영어는 `en/lessons/…`.
- `a`: 그 파일에 **정확히 한 번** 나오는 글자열(두 번 이상 나오면 앞뒤를 더 넣어 하나로 만듭니다. 꼭 여러 곳을 한꺼번에 바꿔야 하면 `"n": 2`처럼 개수를 적습니다).
- `b`: 바꿀 글자열. **`b` 안에 줄바꿈을 넣지 않습니다**(파일의 줄 수가 바뀌면 안 됩니다). 소스에 `\n`이라고 적힌 두 글자는 JSON에서 `\\n`으로 씁니다.
- JSON 문자열 안의 큰따옴표는 `\"`, 역슬래시는 `\\`로 씁니다. 작은따옴표는 그대로 씁니다.
- 파일은 UTF-8로 저장합니다.

## 지켜야 할 것

- **한국어와 영어를 함께 고칩니다.** 한국어 문장의 뜻을 바꿨으면 영어 파일의 대응 문장도 같은 뜻으로 고칩니다. 영어 문장은 보통 한국어와 같은 줄 번호에 있습니다. 영어는 쉽고 정확한 문장으로 씁니다.
- **코드(조건, 좌표, 화살표)를 바꿀 때는 두 파일에 똑같이 넣습니다.** 한글이 없는 줄은 두 파일이 글자 하나까지 같아야 검사를 통과합니다.
- 점검 결과의 `suggest`는 참고입니다. 지시에 따로 적힌 글이 있으면 그 글을 씁니다. 없으면 `truth`에 맞게, 원문과 비슷한 길이로 자연스러운 한국어 문장을 씁니다. 그림 글자(`P.box`의 `title`·`sub`, `P.region` 제목)는 상자에 들어가야 하므로 원문보다 길어지지 않게 합니다.
- **조사를 맞춥니다.** 값이 이어 붙는 자리(`' + x + '을`)는 값에 따라 조사가 틀리지 않게 "값(…)을"처럼 앞말을 두거나 문장을 바꿉니다. 영어 낱말 뒤는 한글 소리로(null·Pool은 ㄹ 받침이라 "로"), 괄호 뒤 조사는 괄호 앞말에 맞춥니다. 표기는 "애너테이션"입니다.
- 설명을 덧붙이려고 문장을 길게 늘이지 않습니다. 틀린 인상을 주는 말을 맞는 말로 **바꾸는** 것이 기본입니다.
- 사실을 지어내지 않습니다. `truth`가 "확인 필요"에 기대고 있고 스스로 확신이 없으면 고치지 말고 보고에 적습니다.
- 지시받지 않은 곳은 건드리지 않습니다. `assume`의 실행 기록은 지시가 없으면 그대로 둡니다.
- 실습 파일의 문자열은 작은따옴표로 싸여 있습니다. `b`에 작은따옴표가 들어가면 문자열이 깨지지 않는지(코드 조각으로서 올바른지) 확인합니다. 문자열 안의 글에 작은따옴표를 새로 넣지 않습니다.

## 적용과 확인

```
node tools/mis_apply_code.js
node tools/i18n/check_en.js <실습 id>
node -e "require('./build.js').loadLessons()"
```

- 첫 명령의 출력 끝에 `못 고침 0`이 나와야 합니다. `못 고침`이 있으면 `a`가 파일과 다르다는 뜻이니 cf 파일을 고쳐 다시 돌립니다(이미 적용된 항목은 건너뜁니다).
- 둘째 명령은 `검사 통과`가 나와야 합니다(`주의`는 있어도 됩니다).
- 셋째 명령은 오류 없이 끝나야 합니다(실습 파일이 문법 오류 없이 읽히는지 봅니다).
- 고친 뒤 문제가 생겨 되돌려야 하면, cf 파일에 `a`와 `b`를 맞바꾼 항목을 **새 파일**(예: cf_06_undo.json)로 적어 적용합니다. git 명령으로 파일을 되돌리지 않습니다.
- 빌드(`node build.js`)와 커밋, 푸시는 하지 않습니다.
